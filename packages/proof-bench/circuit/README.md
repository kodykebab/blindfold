# Direct local funding circuit benchmark

This Go module proves the existing Rust order hash and private funding-root transition using a BN254 Groth16 circuit. It reads the same synthetic prepared fixture as the two-proof benchmark. The public statement includes deployment, owner, batch, step, roots, order hash and both uint256 budgets. Order fields, cumulative totals and commitment blindings are private witnesses.

The circuit uses the original Keccak and Solidity ABI encodings, 128-bit order amounts, the 64-order aggregate bound, canonical zero initialization and bytewise uint256 budget comparisons. It generates and verifies a proof locally without a zkVM or a separate compression stage. The program generates a fresh ephemeral Groth16 setup for each benchmark invocation; these parameters are for benchmarking only.

The checked-in `testdata/prepared.json` was generated by the Rust prepared host and uses synthetic secrets, known plaintext and historical round 1000. It lets this module run independently of the Rust toolchain. From this directory:

```sh
go test -count=1 -v .
go build -o ../results/funding-circuit .
../results/funding-circuit testdata/prepared.json
```

The final JSON reports constraints and separate compilation, setup, proving and native verification durations. `mode=local_funding_component_groth16` identifies this component measurement. Encryption correctness belongs to the separate encryption relation; this executable is a funding benchmark, not an admission verifier. Tests cover the Rust fixture, continuation, both directions, final-step padding, maximum totals, full-width budgets and malformed statements.

Dependencies are pinned in `go.mod` and `go.sum`. The benchmark uses Consensys gnark under Apache-2.0 and gnark-crypto under Apache-2.0; their package sources retain upstream notices.

## Preparation and complete online relations

`PreparationCircuit` checks standard quicknet tlock wrapping and the existing hiding key commitment. It calculates the round hash-to-curve internally and uses pairing bilinearity to compute the same shared secret as tlock. Key, sigma, wrapper and blinding remain private circuit inputs. Scalar derivation selects the first valid candidate among eight attempts, with standard tlock's exact first-byte shift; if no candidate succeeds or it is zero, the client must generate fresh sigma before preparing a key.

`OnlineCircuit` checks the same key commitment, order hash and funding transition, and constructs a canonical single-recipient AGE ciphertext in-circuit. It includes HKDF-SHA256, header HMAC-SHA256, ChaCha20-Poly1305, the final-chunk nonce, canonical round decimal encoding and unpadded base64. The plaintext is the existing 160-byte ABI order-and-salt payload. Canonical files contain one tlock stanza; the independent AGE readers accept this encoding.

Public proof inputs are two 128-bit halves of each Keccak statement digest. The online circuit additionally exposes the two halves of its funding-component statement digest. Settlement derives these values from the canonical public statements; it must not accept unrelated caller-supplied proof inputs. Preparation and online statement bytes match the existing 256-byte and 480-byte ABI journals. The funding-component statement is ten ABI words: chain, settlement, owner, batch, step, old root, new root, budget0, budget1, order hash.

```sh
go build -o ../results/direct-circuit .
../results/direct-circuit --canonical-fixture testdata/prepared.json ../results/canonical-fixture.json
node canonical-interop.mjs ../results/canonical-fixture.json ../results/canonical-interop.json
CIRCUIT_OUTPUT=../results/direct-preparation ../results/direct-circuit --preparation ../results/canonical-fixture.json
CIRCUIT_OUTPUT=../results/direct-online ../results/direct-circuit --online ../results/canonical-fixture.json
(cd ../results/direct-preparation && forge test -vv)
(cd ../results/direct-online && forge test -vv)
```

The canonical fixture command is for synthetic interoperability tests. It preserves the saved fixture's key and wrapper to compare relations, and creates a fresh nonce. A production client consumes each preparation for one order ciphertext.

The prover uses gnark's Solidity-compatible transcript configuration. When `CIRCUIT_OUTPUT` is set, it writes the generated Solidity verifier, verified proof, canonical statement and Foundry tests to that directory. Generated tests check the statement digest, successful verification, each changed public input, a changed proof and a truncated proof. Exported setup parameters remain ephemeral benchmark parameters.

The paired application-boundary harness imports the generated verifiers and checks both proofs together, their common statement prefix, exact ciphertext and the expected owner/deployment/schedule/funding state:

```sh
(cd evm && forge test -vv)
```

It also reads `../../results/canonical-interop.json`, the public interop fixture for `canonical-fixture.json`. To run the existing independent JavaScript check against a direct export, pass its `proof.json` as the export argument to `prepared-interop.mjs`. The `.journal` encoding is shared. After changes to the generated test template, `direct-circuit --export-tests <artifact-directory>` regenerates only that directory's Foundry tests from its exported input count.

## Global multi-token admission

`GlobalFundingCircuit` and `GlobalOnlineCircuit` implement the separate `blindfold.global.*.v1` domains. The public online statement is 16 static ABI words: domain, preparation digest, eight-token registry hash, step, previous root, next root, eight current budgets, order hash and ciphertext hash. The preparation digest is the same canonical preparation statement used by the pair relation. The global online verifier has two public digest limbs; the original pair online verifier has four and is not interchangeable.

The private relation checks token indices in `[0,7]`, nonempty registry slots, different input/output tokens, positive uint128 input, uint128 minimum, step below 64, the exact global order hash, cumulative funding for every token, and the exact canonical AGE ciphertext. Both versions share the encryption implementation. The global plaintext is `abi.encode(owner, uint8 tokenIn, uint8 tokenOut, uint128 amountIn, uint128 minAmountOut, bytes32 salt)`.

Generate a fresh preparation witness with OS entropy:

```sh
cargo run --manifest-path ../Cargo.toml --locked --release --bin global-prepare -- context.json private-preparation.json
```

`context.json` uses `{chain_id, settlement, owner, batch, round}`, with addresses as 20-element byte arrays. The output is private, created with mode 0600 on Unix, and never overwrites an existing file. It contains a fresh AGE key, encryption randomness and hiding blinding. Do not use the checked-in synthetic fixtures for user orders.

Global online input:

```json
{
  "preparation": "private-preparation.json",
  "tokens": ["0x...sorted token0...", "0x...token1..."],
  "input": 0,
  "output": 1,
  "amount": "100",
  "minimum": "90",
  "step": 0,
  "totals": ["0","0","0","0","0","0","0","0"],
  "budgets": ["1000","1000","0","0","0","0","0","0"],
  "oldBlind": "0x...32 bytes..."
}
```

Read budgets from `GlobalAuction.budgets(owner)`: they already subtract the next admission's deposit and fee. Use the previous accepted state's totals/blinding/step for subsequent orders. Omitted salt receives cryptographic randomness in the CLI. Slots beyond the registry are zero. Preparation paths resolve from the process working directory. An account cannot enter another batch while it has open global commitments.

```sh
# Explicit local development setup; retain keys for subsequent proofs.
CIRCUIT_KEYS=../results/global-keys CIRCUIT_SETUP=1 CIRCUIT_OUTPUT=../results/global-first go run . --global-online global-input.json
# Same circuit identity and verifier, new ciphertext and proof; no setup.
CIRCUIT_KEYS=../results/global-keys CIRCUIT_OUTPUT=../results/global-next go run . --global-online global-input.json
# Preparation uses its own keys and output directory.
CIRCUIT_KEYS=../results/preparation-keys CIRCUIT_SETUP=1 CIRCUIT_OUTPUT=../results/global-preparation go run . --preparation private-preparation.json
```

Key loading checks the serialized compiled circuit's SHA-256 and mode. Local setup is explicit and refuses a nonempty key directory. `global-state.json` contains the private next reservation state, plaintext/salt and ciphertext; `proof.json` contains the proof/public statement. Use a distinct output directory for each run and consume it only after successful exit. Without `CIRCUIT_KEYS`, the command remains an ephemeral benchmark that creates fresh verifier parameters.

Real-proof integration uses the fixed synthetic preparation context at chain 130, batch 7, round 1000, token addresses `0x1001`–`0x1003`, input 1, output 2, amount 100, minimum 90, explicit zero salt, budgets `[1000,1000,1000,0,0,0,0,0]`. Generate matching preparation and online exports into `results/global-preparation` and `results/global-online`, then run:

```sh
(cd ../global-evm && forge test --match-contract GlobalAdmissionIntegrationTest -vv)
node global-interop.mjs ../results/global-online/global-state.json
```

The integration locates actual auction code at the fixture's bound address, copies constructor state, and exercises actual vault custody. The independent JS check verifies the recorded drand signature, decrypts AGE using tlock-js, and recomputes Solidity order/registry/funding hashes. Production setup and circuit-review gates are recorded in REVIEW.md.
